\section{Publication-Focused Roadmap Without New Physical Validation}
\label{sec:roadmap}

\paragraph{Status note (July 29, 2026).}
The independent security-predictor architecture is now implemented. Numerical
campaign counts and findings below describe the completed pre-revision replay
study and remain useful as provenance, but its alarm thresholds, attack
summaries, and figures must be regenerated before they are treated as current
results. This regeneration uses the existing logs and requires no rover run.

This roadmap is optimized for the user's current constraint: pursue the
strongest possible conference or journal submission \emph{without} collecting
new independent ground-truth data or an untouched prospective validation set.
That constraint should be stated explicitly in the paper. Under it, the paper
should be framed as a real-log, mechanism, and security-limits study rather
than as a fully validated deployed defense.

    validation: approximately 60--68\%.} The ceiling is limited by the lack of

\subsection{Completed Evidence Base}

The completed no-new-data package consists of:

\begin{itemize}
    \item A checksum-identified 20-run UGV01 design corpus:
    \[
        2\ \text{speeds} \times 2\ \text{surfaces} \times
        5\ \text{trials}=20\ \text{runs}.
    \]

    \item A frozen main campaign with 24 attack profiles, three attack start
    times, 11 detector variants, 1,440 unique attack-run-start combinations,
    and 15,840 detector-run evaluations.

    \item An expanded replay-only grid with 44 attack profiles, 2,640 unique
    attack-run-start combinations, and 29,040 detector-run evaluations.

    \item External baselines: GPS jump, raw digital-twin residual, fixed NIS,
    robust innovation gate, Huber EKF, CUSUM whitened innovation, and
    innovation-matching adaptive EKF.

    \item Adaptive variants: naive residual-coupled adaptation, frozen-clean
    covariance, GPS-independent adaptation, and evidence-gated adaptation.

    \item Post-campaign tables for tolerance-exceeding paired divergence at
    0.25, 0.5, 1, 2, and 5 m.

    \item Paired detector differences with physical-run-clustered bootstrap
    intervals.

    \item Gate-behavior summaries showing residual-feedback activation,
    independent-evidence fraction, and covariance trace ratios.

    \item Runtime benchmark showing steady-state offline replay cost of about
    2.3--2.6 ms per update after warm-up.

    \item Provenance hashes for the manifest, campaign outputs, thresholds,
    and configuration files.
\end{itemize}

\subsection{Defensible Paper Claim}

The paper should use the following claim hierarchy.

\paragraph{Primary claim.}
Residual-coupled adaptive uncertainty creates a measurable feedback path under
semantic GPS drift:
\[
    a_k \rightarrow \nu_k \rightarrow \widehat{Q}_k
    \rightarrow P_k^- \rightarrow S_k \rightarrow d_k.
\]
On real UGV01 logs, this feedback path can increase tolerance-exceeding paired
divergence before alarm relative to several fixed and robust baselines.

\paragraph{Secondary claim.}
Slow semantic GPS drift is substantially harder than abrupt step bias under
the current low-cost rover, GPS receiver, route scale, and matched run-level
false-alarm calibration.

\paragraph{Design claim.}
GPS-independent and evidence-gated adaptation reduce the direct
attacked-GPS-to-covariance feedback path, but the current evidence does not
prove that evidence gating fully solves the slow-drift problem.

\paragraph{Explicit non-claim.}
The current paper must not claim prospective field deployment performance,
physical trajectory harm, or final run-level false-alarm validity because
independent ground truth and untouched prospective validation are absent.

\subsection{Top-Venue Maximization Plan Without New Data}

The following work can still improve the paper without collecting new rover
runs.

\subsubsection{Stage 1: Finish the Theory Package}

\begin{enumerate}
    \item Keep the covariance theorem scoped to linear Kalman filters and
    locally linearized paired replay with identical $F_k$, $H_k$, $R_k$, and
    initial covariance.

    \item Present matrix inverse monotonicity as a supporting proposition,
    not as the main theoretical contribution.

    \item Expand the attack-to-adaptation feedback loop into a theorem or
    proposition that bounds accepted covariance growth as a function of attack
    magnitude, adaptation rate, covariance cap, and gate pass count.

    \item Add an oracle detectability bound showing the best single-update
    Gaussian mean-shift detector under the same $S_k$.

    \item Connect the single-update bound to the implemented three-of-five
    persistent alarm using a binomial approximation and an empirical
    correlated-window caveat.

    \item Add a safe-adaptation condition:
    \[
        \epsilon^2 u^\top(S_k^0+\Delta S_{\max})^{-1}u
        \geq \lambda_{\min}.
    \]
    This makes the security tradeoff explicit.
\end{enumerate}

\textbf{Exit criterion.} Theoretical results explain why covariance inflation
reduces normalized attack evidence and clearly state their assumptions.

\subsubsection{Stage 2: Strengthen Statistical Reporting}

\begin{enumerate}
    \item Promote paired detector differences to a main result table,
    especially for 0.05 m/s cross-track drift:
    naive adaptive minus fixed, robust gate, Huber, CUSUM, GPS-independent,
    and evidence-gated variants.

    \item Report tolerance-exceeding paired divergence before alarm at
    0.25, 0.5, 1, 2, and 5 m rather than only at 5 m.

    \item Use physical-run-clustered bootstrap intervals everywhere. Do not
    treat multiple attack starts from the same physical log as independent
    physical experiments.

    \item Include threshold-sweep curves or tables showing detection
    probability and paired-divergence probability versus run-level false
    alarm.

    \item Add a small power-analysis paragraph explaining how many prospective
    runs would be needed to validate false-alarm rates or paired-difference
    effects in future work.
\end{enumerate}

\textbf{Exit criterion.} Every headline number has an interval or is clearly
labeled as a deterministic artifact count.

\subsubsection{Stage 3: Make Baseline Comparison Hard to Dismiss}

\begin{enumerate}
    \item Keep the compact baseline algorithm table with score, state update,
    adaptation input, persistence rule, and attack influence path.

    \item Explain that all baselines use the same benign run-level threshold
    locking procedure.

    \item Discuss where each baseline is expected to help: GPS jump for abrupt
    offsets, CUSUM for persistence, Huber and robust gate for outlier-like
    corruption, GPS-independent adaptation for feedback removal, and
    evidence gating for conditional adaptation.

    \item Add a short paragraph explaining why no baseline dominates all
    conditions. This helps frame the result as a security-limit map rather
    than a failed method comparison.
\end{enumerate}

\textbf{Exit criterion.} A reviewer cannot say the proposed method was
compared only against weak or unfair baselines.

\subsubsection{Stage 4: Improve Related Work and Positioning}

\begin{enumerate}
    \item Expand related work into separate subsections:
    secure state estimation, GPS/GNSS spoofing and slow drift, adaptive Kalman
    covariance estimation, robust/sequential residual detection, digital-twin
    security, and edge robotic monitoring.

    \item Increase the bibliography to roughly 30--40 references for a
    conference-style draft.

    \item Add a novelty comparison table with columns for real physical logs,
    adaptive covariance security, slow drift, matched false alarm, edge
    timing, physical ground truth, and live validation.

    \item Avoid saying all prior work assumes fixed covariance. Use the more
    careful claim that many classical analyses assume known or stationary
    noise models, while the security effects of online residual-driven
    adaptation are less directly studied.
\end{enumerate}

\textbf{Exit criterion.} The paper's novelty is clear even though physical
ground truth is absent.

\subsubsection{Stage 5: Reframe Results as Security Limits}

\begin{enumerate}
    \item Use the title and abstract language:
    ``Security Limits of Adaptive Uncertainty in Edge Digital Twins'' rather
    than ``GPS spoofing defense''.

    \item Treat weak small-attack detection as a capability-map result, not as
    a failure to hide.

    \item Emphasize that ordinary robust and sequential baselines also fail to
    detect slow drift at the locked operating point.

    \item State that the result is valuable because it identifies when the
    digital twin lacks enough statistical sensitivity to make a reliable
    security decision.
\end{enumerate}

\textbf{Exit criterion.} The paper reads as a measurement and mechanism study
with careful security claims, not as an overclaimed defense paper.

\subsubsection{Stage 6: Package Reproducibility}

\begin{enumerate}
    \item Create a clean artifact folder containing raw logs or checksums,
    campaign configuration, locked policies, result CSVs, figures, and the
    exact commands needed to regenerate them.

    \item Include \texttt{results\_provenance.json} in the artifact package.

    \item Pin dependency versions beyond the current \texttt{requirements.txt}
    where possible.

    \item Add a one-command or short-command sequence in the paper and README:
    main campaign, post-campaign tables, threshold sweep, expanded grid, and
    runtime benchmark.

    \item Freeze the final figure and table paths so the PDF and repository
    agree exactly.
\end{enumerate}

\textbf{Exit criterion.} An external reader can reproduce the reported
offline results from the repository package.

\subsection{Optional No-New-Data Extensions}

These are useful but should not distract from paper cleanup:

\begin{itemize}
    \item Run the optional combined GPS-content plus buffered delay/jitter
    campaign and report it as an A3 replay robustness extension.

    \item Add an offline oracle strategic attacker that selects high
    uncertainty windows from existing logs. This can provide an upper bound
    without new physical runs.

    \item Add a public trajectory dataset or synthetic benchmark as a
    secondary external sanity check, if it can be integrated without bloating
    the paper.

    \item Add ROC-style figures from the threshold sweep, but keep the frozen
    matched operating point as the primary comparison.
\end{itemize}

\subsection{Remaining Ceiling Without New Validation}

Even after all no-new-data improvements, the following limitations remain:

\begin{itemize}
    \item paired replay divergence is not true physical trajectory error;
    \item $1/20$ leave-one-run-out false alarms are not prospective validation;
    \item live edge behavior is not proven by offline replay runtime;
    \item attacks are replay-injected rather than live semantic attacks;
    \item generalization beyond one rover, one GPS module, one route family,
    and two surfaces remains unproven.
\end{itemize}

Therefore, the best realistic framing without new data is a strong
mechanism-and-limits paper. The estimated publication potential after the
roadmap above is:

\begin{itemize}
    \item \textbf{good specialized conference: high;}
    \item \textbf{strong journal: moderate to good if theory and artifact
    quality are strong;}
    \item \textbf{top/very strong main-track conference: possible but risky;}
    \item \textbf{top-tier journal: possible only if reviewers accept the
    offline real-log limitation as a valid scope.}
\end{itemize}
